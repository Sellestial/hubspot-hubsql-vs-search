# Article review 1

Codex (gpt-6-sol) reviews the first article draft.

**Verdict: not ready to publish.** The main result is useful, but the headline treats a comparison between two different models as proof that code caused the difference. The timing figure also says both tools gave the same answers, although the scored results differ.

1. **“It depends on whether your AI can run code.”** This appears in the article, title and cover. Claude without code and Codex with code used different models and environments. The test supports comparisons *within* each model, but does not isolate the effect of switching code on. Replace the title with **“HubSpot search or HubSQL for AI agents? What changed in our Claude and Codex tests”** and the takeaway with: **“In our no-code Claude setup, adding HubSQL raised accuracy from 19/30 to 28/30. In our code-using Codex setup, search answered 30/30, though it took longer on six heavier questions.”** Keeping the causal headline requires a same-model test with code enabled and disabled.

2. **“Both tools gave the same answers.”** The subtitle of [fig-time.png] contradicts Codex’s 30/30 with search and 28/30 with HubSQL. The article’s “HubSQL got the same answers 2 to 6 times faster” repeats the problem. Replace with: **“The HubSQL setup had lower median response times on these six questions. Across all ten, it answered 28/30 correctly versus 30/30 for search.”** Say whether the plotted medians include incorrect runs; for a speed-to-correct-answer claim, recalculate using correct runs.

3. **“Search” / “HubSQL”** on the figures reads like a choice between two separate tools. The HubSQL setup had **all the search tools plus** `query_crm_data`. Rename the bars **“Search tools only”** and **“Search tools + HubSQL”** throughout. This makes clear what was actually changed between setups. See [facts.md].

4. **“HubSQL matches the words anywhere and in any order … Search’s CONTAINS_TOKEN works the same way.”** The recorded counts do not establish that rule: the HubSQL pattern returned 8,920, “both words anywhere” returned 8,916, and reversing the pattern returned 8,922. Equal counts for one search pattern also do not prove identical matching sets. Replace with: **“On this portal, `LIKE '%revenue operations%'` returned 8,920 titles, while a case-insensitive literal substring check of the export found 8,147. Reversing the HubSQL pattern returned 8,922. The MCP search phrase filter also returned 8,920. These filters did not implement the literal substring rule in our question.”**

5. **“Most wrong answers came from how HubSpot matches text”** and the red explanation in [fig-causes.png] assign too much causality. Twenty-seven errors occurred *on* two text-filter questions, but three Claude errors on the RevOps question had other reported answers. The California mismatch was in MCP search; HubSQL returned the reference count. Replace the heading with **“Twenty-seven of 35 misses were on two text-filter questions.”** Replace the figure subtitle with **“Red: questions with text-matching pitfalls; these bars count wrong answers, not a proven cause for every run.”**

6. **“10 questions drawn at random from 50.”** Fifteen candidates were excluded, two were drawn per group, and the no-repeat rule was added after an initial draw but before scored runs. A skeptical reader will object to the implied unrestricted draw. Replace with: **“A separate AI drafted 50 questions. We applied published eligibility rules to remove 15, then used a recorded seed to draw two from each of five groups. The no-repeat rule was added after an initial draw, before any scored run.”** See [selection.md].

7. **“300 runs in total”** beside four accuracy bars can imply those bars summarize all 300. They show the four plain setups, or 120 runs. The other 180 used guides or extra shell/Python access. Add to [fig-accuracy.png] and the cover: **“Plain setups shown: 120 runs. Full study: 300 runs including guide and shell/Python variants.”** In the method, say that all six Codex setups could already call tools through JavaScript.

8. **“Search can count anything you can filter on, but it can’t group or average.”** “Anything” is contradicted by the California filter’s misleading total, and “can’t group or average” confuses a tool operation with what an agent can compute from fetched records. Replace with: **“The MCP search tool can return counts for many filters, but its totals can reflect unexpected text matches. It has no group-by or average operation, so the no-code Claude setup had to work from records returned into the conversation.”**

9. **“All 35,230 SEO scores in 184 calls”** mixes two measures: [facts.md] records 180 page reads and a median of 184 tool calls. “It paged through every US company” is not established by the supplied facts. Replace with: **“For the SEO question, Codex search read all 35,230 qualifying records in 180 page reads; its median across runs was 184 tool calls.”** Remove the US-company sentence unless the run log supports it. Also name the SEO population: companies marked as using HubSpot by BuiltWith and having a score, rather than implying all companies.

10. **“Search used up to 476 tool calls per answer, HubSQL up to 22.”** In the time figure, 476 and 22 are **medians for the industry question**, not documented maxima. Replace with: **“For the contact-industry question, median tool calls were 476 with search tools only and 22 with HubSQL available.”** “On the 4 light questions both took under a minute” should likewise say **“median time was under a minute”**; individual-run maxima are not supplied.

11. **“With HubSQL, both answers took about 10 seconds and one query.”** One query is documented for both Claude examples, but only the industry query has a recorded roughly 10–15 second time. Replace with: **“Claude answered both questions correctly in all three HubSQL runs, using one query per answer. The industry query took roughly 10–15 seconds.”**

12. **“It told the agent to count with filters and read the total, which is exactly where both text problems sit. The HubSQL guide changed little.”** The aggregate facts do not establish that the guide caused Codex’s errors. Claude’s HubSQL guide also scored 25/30 versus 28/30 without it. Replace with the observed scores: **“Guides changed results in different directions: Claude search rose from 19/30 to 22/30, while Codex search fell from 30/30 to 26/30. For HubSQL, Claude fell from 28/30 to 25/30 and Codex rose from 28/30 to 29/30.”** Attribute a mechanism only if the published transcripts demonstrate it.

13. **“With LIMIT 60 or more they were exact”; “which made every answer slower”; “so a misread question can’t explain a difference.”** Each turns a limited observation into a rule. Replace respectively with: **“In the earlier pilot, LIMIT 60, 200 and 500 matched the comparison counts; LIMIT 10 sometimes fell short.”** **“Codex ran at extra-high reasoning effort; timings include model processing.”** **“Every run received the same detailed scoring definition, though an agent could still misread it.”** Restrict “no code isn’t an option” to **“this Codex CLI setup.”**

14. **“Red: the setup that guessed.”** The Claude search runs often flagged uncertainty, so “guessed” is an unfair label. Use **“Red: lowest score in this test”** or remove the legend. For a one-second read of the time figure, specify **“US company states,” “ICP company HQ countries,”** and **“Contacts with RevOps titles.”** The cover and accuracy figure repeat the same four bars; consider using the cover alone and removing the repeated body figure. The overall tone is restrained once “wins,” “guessed,” and the broad causal claims are tightened.

15. **“HubSpot turned on HubSQL for our portal this month. It’s a private beta”; “the connector that AI assistants like Claude and ChatGPT use”; “[REPO LINK].”** The first two product/access claims are not verified in the supplied files, and ChatGPT was not tested. Supply a source or narrow the opening to **“We tested HubSQL through HubSpot’s remote MCP server on our portal. MCP lets an AI assistant call HubSpot tools.”** Replace the repository placeholder with a working public link and verify that it contains the promised harness, questions, rules and results. Until then, remove the “Code” paragraph’s availability claim.

The essential pre-publication changes are **1–7, 10 and 15**. They correct the experimental claim, the figure’s accuracy statement, the matching explanation, the selection description and the audit link.
